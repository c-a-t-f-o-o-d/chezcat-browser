EFF: HTTP-header fingerprint

Start with EFF's server-rendered report. It compares the request's user agent, Accept headers, cookie presence and Do Not Track header with its visitor dataset.

This endpoint does not measure JavaScript properties. Fields marked "no javascript" are placeholders in this report. It does not run the full tracking test.

Open EFF's header report

A distinct User-Agent can identify this browser within EFF's sample by itself. Fewer exposed features do not guarantee that a fingerprint is shared with other visitors. The listed identifying bits are not added together.

Use Ctrl+J to turn scripting off if you want to inspect the page without running any of its scripts. EFF generates the report on its server either way.

EFF: Cover Your Tracks

The full test combines browser fingerprinting with simulated trackers across several sites. Its current scripts need modules, a larger JavaScript subset, frames, timers and browser APIs that are still missing here.

Full test compatibility is incomplete. A test that stops, or a feature that is unavailable, is not a measured privacy score.

Uniqueness describes the site's sample of recent visitors. An unusual browser can stand out even while exposing fewer features.

GRC: ShieldsUP!

ShieldsUP probes the public Internet connection reaching GRC. Port results concern that connection, including its router or firewall. Its browser-header check instead shows information in the web request.

Open GRC, review its introduction, then choose the check you want. This build supports native POST form submission for sites that use a Proceed button.

HTTPS offers TLS 1.3 and TLS 1.2, including the older ECDHE-RSA AES-CBC combinations. TLS 1.2 servers that omit Extended Master Secret can use a full handshake. A connection error means the test did not run. Ctrl+I now preserves the selected version, cipher and response progress even if receiving the page fails. Check-Connections.cmd saves those details to a text file.
