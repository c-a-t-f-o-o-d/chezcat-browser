Request blocking

ChezCat can stop matching automatic image, script, stylesheet and font requests before they are sent. Rules also apply to redirect destinations.

Try it locally

Start Run-Http-Demo.cmd, then open this workshop over HTTP. Local files are not network requests and are not filtered.

In Settings, enable Block ads / trackers with local request rules. Open Request-blocking rules, add these two rules, choose Done, then Apply:

path:/pages/blocking/
@@path:/pages/blocking/allowed/

With those rules enabled, the first banner, external script and extra stylesheet below are blocked. The second banner is an allow exception. F12 > Network or Ctrl+I shows each decision; the server terminal shows the requests actually received.

Rule reference

ads.example.com matches that host and its subdomains.

path:/ads/ matches a path prefix on any host.

url:https://example.com/ads/ matches an origin and path prefix.

@@path:/ads/allowed/ allows a matching request through this filter. The browser's origin and certificate rules still apply.

This is a small local request blocker. It has no automatic filter downloads, cosmetic element hiding or full EasyList syntax. Existing profiles start with blocking disabled; the optional starter host list is intentionally small.
