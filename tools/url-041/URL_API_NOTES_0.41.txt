ChezCat 0.41 - bounded JavaScript URL and URLSearchParams
=====================================================

Purpose and concrete failure
----------------------------
Verified 0.40 has no JavaScript URL or URLSearchParams constructor. All 40
preimplementation original API comparisons fail there. This capability supports
ordinary search-query construction and URL manipulation in page scripts. It
makes no claim that Google or Bing now work end to end.

Implementation
--------------
New src/url_api.rs implements original HTTP(S) URL parsing and local value
objects. New src/url_api_tests.rs contains targeted regression tests. These
objects have unforgeable runtime slots. URL.searchParams has stable identity;
URL search/href replacement changes the same query object, and query mutations
update the owning URL. Mutations preflight limits and commit both slots together.
Object.freeze does not prevent changes to these internal slots.

Supported scoped URL behavior: absolute and relative HTTP(S) URLs; special-URL
slashes, input whitespace handling, dot segments including percent-encoded dot
forms, UTF-8 percent encoding, ASCII domain canonicalization, WHATWG numeric IPv4
forms, compressed IPv6, credentials, default ports, empty query/fragment
preservation; href, origin, protocol, username, password, host, hostname, port,
pathname, search, hash, searchParams; component getters and setters; toString,
toJSON, URL.canParse, URL.parse. Malformed supported inputs throw TypeError or
produce false/null in the static APIs. Invalid non-href component mutations
preserve the relevant previous component, including host/port partial parsing.

Supported query behavior: string, record and iterable-pair construction; UTF-8
form encoding with spaces as plus; forgiving percent decoding and replacement
for invalid UTF-8; append/get/getAll/set/has/delete/sort/toString/size;
keys/values/entries/default iterator and forEach. Optional undefined values for
has/delete are treated as omitted. Sort is stable and compares UTF-16 code units.
Methods and iterable conversion share the existing callback and iterator budget.
Direct next() calls can see pairs appended after a previous done result, as
required for these live pair iterators. Conversion callbacks can change the
current object; operations use the current slot after conversions complete.

Bounds and security
-------------------
URL input and serialization: 16 KiB. Query input, decoded string data and a single
serialized query: 64 KiB. Query pairs: 1,024. Retained strings and allocated pair
capacity (including empty-pair metadata) share the existing 2 MiB document value
budget. Objects, properties, call depth, execution steps and copy-work retain
existing runtime limits. Native parsing loops also have finite input limits.
All resource-limit failures stay fatal; script catch/finally cannot resume the
exhausted job. A query mutation that would exceed the owning URL limit leaves
both objects and retained accounting unchanged.

This module is separate from src/url.rs, the stricter networking URL parser.
It does not fetch, resolve DNS, alter current-document origin, change TLS, change
CSP, relax cross-origin checks, or change privacy/profile defaults. Node is used
only by development comparisons; it is not a browser dependency.

Explicit unsupported boundaries
-------------------------------
Only HTTP(S) URLs are implemented. Non-HTTP(S), Unicode IDNA conversion and IDNA
validation of ASCII ACE (xn--) host labels produce explicit capability errors,
including through canParse/parse; those cases are not disguised as malformed
supported URLs. No file, data, blob, opaque-path, object-URL or other scheme
support is claimed. Host handles cannot acquire URL/iteration capabilities.
The pre-existing interpreter scalar-string/lone-surrogate restriction and
prototype/Symbol.toStringTag limitations remain. No full WHATWG/Web IDL or
browser compatibility claim is made.
