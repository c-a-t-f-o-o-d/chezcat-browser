# Pinned single-byte encoding data

This directory retains the normative input data used by ChezCat's original
single-byte decoder. No browser engine or third-party decoder implementation
is included.

## Source and provenance

The source is the [WHATWG Encoding Standard repository](https://github.com/whatwg/encoding)
at commit [`7d2e3e08e11f57ba1b080390b490d53648c6f69c`](https://github.com/whatwg/encoding/tree/7d2e3e08e11f57ba1b080390b490d53648c6f69c).
The retained files are the exact bytes of `encodings.json`, `LICENSE`, and the
27 selected `index-*.txt` files at that revision. During acquisition, each file's
Git blob identifier and byte length were checked against that commit's Git tree.

[`manifest.json`](manifest.json) records the revision, repository, file paths,
byte lengths, Git blob SHA-1 identifiers, and SHA-256 hashes. The offline
generator verifies all of these recorded file identities before using the data.
An upstream data update therefore requires an explicit manifest and generator
revision change followed by review and regeneration.

## Selection and representation

The `Legacy single-byte encodings` group in the pinned `encodings.json` contains
28 encoding names and 168 labels. ISO-8859-8 and ISO-8859-8-I have separate
identities and labels but share the ISO-8859-8 index, giving 27 distinct mapping
tables. Labels for other encoding families remain in the unmodified source JSON
but are not emitted by this generator.

The generated Rust module preserves ASCII bytes directly. Each table contains
128 entries for bytes `0x80` through `0xff`; an omitted upstream pointer is
represented by the `0xffff` sentinel and produces a decoding error for the caller
to handle. The generator verifies that every selected mapped value is a valid
BMP scalar distinct from that sentinel. It does not substitute platform codepage
tables or fill omitted pointers. This matters for mappings such as the defined
Windows-1252 control code at byte `0x81` and the undefined ISO-8859-6 byte `0xa1`.

`SingleByte::from_label` accepts already normalized labels. The integrating
decoder performs the standard's ASCII case and whitespace normalization and
owns replacement versus fatal error handling. `x-user-defined` is arithmetic
and is handled separately; it has no index file in this selection.

Index descriptions include literal C1 controls. The generator splits source
rows only at LF, preserving those description characters when identifying rows.

## Reproduce and check

From the repository root, using Python 3 and its standard library:

```console
python tools/generate_single_byte_encodings.py
python tools/generate_single_byte_encodings.py --check
python tools/check_single_byte_encodings.py
```

Generation is deterministic and offline. The `--check` command compares the
generated bytes with `src/text_encoding_single_byte.rs` without rewriting it.
The focused data checks reject changed inputs, invalid paths, repeated inputs,
invalid index rows and unsupported scalars. Separate Rust tests compare actual
decoding with these retained normative files, including all byte values and
the declared labels.

Only the generated Rust tables and original lookup code are used at runtime.
The raw files, Python generator and manifest do not run during browser startup,
load resources over the network, or add Rust dependencies.

## Scope

This selection supplies the legacy single-byte portion of the F02 encoding
foundation. It does not establish complete Encoding Standard or HTML encoding
conformance. Multibyte encodings, byte-stream/document encoding selection,
HTML prescan and parser restart behavior, and XML encoding policy have separate
requirements and evidence.
